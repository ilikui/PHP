# 01｜环境与运行机制

## 学习目标

- 区分 PHP 解释器、Web 服务器与浏览器。
- 能通过 CLI 执行脚本并检查语法。
- 了解 `php.ini`、扩展与 SAPI 的基本作用。
- 知道为什么生产环境不能公开 `phpinfo()`。

## 1. PHP 如何运行

```mermaid
flowchart LR
    A[编写 .php 文件] --> B{运行方式}
    B --> C[CLI 命令行]
    B --> D[浏览器 HTTP 请求]
    C --> E[PHP CLI 解释执行]
    D --> F[Web 服务器 / PHP-FPM]
    F --> E
    E --> G[输出文本或响应内容]
    G --> H[终端或浏览器]
```

CLI 适合脚本、批处理和命令行工具；Web 场景中，浏览器发送 HTTP 请求，服务器把 PHP 代码交给相应的 PHP 运行环境处理，再将响应返回浏览器。浏览器通常接收的是输出结果，而不是 PHP 源代码。

## 2. 最小示例

创建 `hello.php`：

```php
<?php
declare(strict_types=1);

echo "Hello, PHP!", PHP_EOL;
echo 'PHP version: ', PHP_VERSION, PHP_EOL;
```

执行：

```bash
php hello.php
php -l hello.php
```

`PHP_EOL` 是当前平台的换行符；`php -l` 用于检查语法，不会执行脚本。

## 3. 常见概念

| 名称 | 用途 |
| --- | --- |
| PHP CLI | 从终端执行 PHP 脚本 |
| SAPI | PHP 与外部环境交互的接口类型 |
| php.ini | 配置错误报告、扩展及运行行为 |
| Extension | 为 PHP 增加数据库、字符串处理等能力 |
| Composer | 管理 PHP 项目依赖和自动加载 |

CLI 与 Web 运行时可能加载不同的配置文件，排查“命令行能运行、网页不能运行”时，应分别检查各自的配置与扩展。

## 4. 错误报告

学习环境中可以开启错误报告，帮助发现问题：

```php
<?php
error_reporting(E_ALL);
ini_set('display_errors', '1');

// 仅用于演示：未定义变量会触发诊断信息。
echo $notDefined;
```

不要把 `display_errors=1` 直接用于生产环境。生产环境应记录错误日志，避免向用户暴露路径、配置和内部细节。

## 5. 关于 phpinfo()

`phpinfo()` 可以展示 PHP 版本、扩展、配置项及环境信息。它适合本地排查环境问题，但可能泄露服务器信息。检查完成后应删除相关公开页面。

## 练习

1. 查看本机 PHP 版本与已加载模块。
2. 故意写一个语法错误，使用 `php -l` 观察结果。
3. 比较 CLI 与 Web 环境的 PHP 版本和配置文件。
4. 解释为什么 PHP 源码不应被 Web 服务器当作普通文本直接公开。
